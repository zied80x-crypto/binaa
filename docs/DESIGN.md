# التصميم التقني — مقاول بناء

## 1. البنية المعمارية

```
UI (Jetpack Compose, RTL)  ──►  ViewModel / produceLive  ──►  Repository  ──►  Room DAOs  ──►  SQLite (binaa.db)
                                                               │
                                                               ├── domain/ (PayrollWeek, PayrollCalculator, Money) — منطق نقي مختبَر
                                                               ├── audit_log — كل تعديل مالي
                                                               └── BackupManager — نسخ تلقائي بعد كل عملية مالية
```

- **MVVM + Repository**: الشاشات لا تلمس قاعدة البيانات مباشرة لأي كتابة؛ كل كتابة تمر عبر `Repository` داخل `withTransaction` مع التحقق والتدقيق.
- **تحديث تلقائي**: `Repository.changes` يصدر إشارة عند أي تغيير في الجداول (Room invalidation)، فتُعاد الحسابات (التوقع، الأرصدة) فوراً.
- **قابلية المزامنة لاحقاً**: كل صف له معرّف ثابت و`createdAt/updatedAt`، ولا يوجد حذف للسجلات المالية (إلغاء فقط)، ما يسهّل إضافة مزامنة سحابية لاحقاً.

## 2. قاعدة البيانات

| الجدول | الحقول الأساسية | القيود |
|---|---|---|
| `projects` | name, ownerPhone, address, startDate, status, notes | — |
| `project_payments` | projectId, amount, date, method, notes, voided, voidReason | FK → projects (RESTRICT). لا تعديل ولا حذف: إلغاء مع سبب |
| `workers` | fullName, phone, dailyWage, startDate, status, notes | اسم فريد |
| `attendance` | workerId, date, **weekStart**, status, projectId, **wageSnapshot**, amount | **UNIQUE(workerId, date)** يمنع التكرار |
| `advances` | workerId, amount, timestamp, **weekStart**, notes, voided | تنتمي لأسبوع واحد فقط |
| `payrolls` | workerId, weekStart, أيام، gross, advances, net, paidAmount, paidAt, corrected | **UNIQUE(workerId, weekStart)** يمنع الدفع مرتين |
| `audit_log` | timestamp, entityType, entityId, action, details | إضافة فقط |

- المال: `Long` بالمليم (1 د.ت = 1000 مليم). الضرب (نصف يوم) عبر `BigDecimal` مع تقريب `HALF_UP`. لا `Float/Double` إطلاقاً.
- التواريخ: `epochDay`؛ الأوقات: `epochMillis`.

## 3. منطق الرواتب وقاعدة الأحد

**أسبوع الدفع يُعرَّف بالأحد الذي يفتحه**، ويغطي الأحد ← السبت، ويُدفع يوم ذلك السبت:

```
weekStart(date) = date − (dayOfWeek % 7) أيام      // الأحد=0، الاثنين=1 ... السبت=6
```

| التاريخ | weekStart | يُدفع يوم |
|---|---|---|
| الاثنين 09/11 … السبت 14/11 | الأحد 08/11 | السبت 14/11 (أسبوع A) |
| **الأحد 15/11** | **الأحد 15/11** | **السبت 21/11 (أسبوع B)** |
| الاثنين 16/11 … السبت 21/11 | الأحد 15/11 | السبت 21/11 (أسبوع B) |

لأن كل تاريخ يُطابَق مع أسبوع واحد بدالة رياضية، **يستحيل** احتساب الأحد في الأسبوع السابق أو احتسابه مرتين. يُخزَّن `weekStart` مع كل سجل حضور وكل تسبقة.

```
الإجمالي الأسبوعي  = Σ (الأجر المحفوظ × المعامل)   حاضر=1، نصف=0.5، غائب=0
الباقي             = الإجمالي − Σ التسبقات غير الملغاة لذلك الأسبوع
الرصيد المستحق     = Σ كل المكتسب − Σ كل التسبقات − Σ كل المدفوع     (دفتر حسابات)
```

**التوقع ليوم السبت**: الأيام المسجلة بقيمتها الحقيقية + الأيام غير المسجلة من الاثنين إلى السبت تُحتسب حضوراً كاملاً (منذ تاريخ بداية العامل) − التسبقات. الأحد يدخل فقط إن سُجّل. العمال المدفوعون يُستثنون.

**تأكيد الدفع**: يكتب لقطة ثابتة في `payrolls` (لا يحدث تلقائياً أبداً). يمكن دفع مبلغ مختلف عن الصافي: الفرق يبقى في الرصيد ولا يختفي مع بداية أسبوع جديد.

**تصحيح أسبوع مدفوع**: أي تعديل لحضور/تسبقة في أسبوع مدفوع يرمي `PaidWeekLockedException`؛ الواجهة تطلب سبباً إجبارياً (+ رمز التصحيح إن كان مفعّلاً). اللقطة المدفوعة تبقى كما هي، يُعلَّم الأسبوع «مُصحَّح»، ويُسجَّل في `audit_log`، والفرق يظهر في رصيد العامل.

## 4. الشاشات

1. **الرئيسية**: بطاقة التوقع لرواتب السبت، حاضر/نصف/غائب/غير مسجل اليوم، المشاريع النشطة، العمال، المستحقات، المقبوضات، آخر العمليات، أزرار سريعة.
2. **الحضور**: تنقل بين الأيام، تنبيه الأحد، مشروع افتراضي لليوم، لكل عامل: حاضر / نصف / غائب / مشروع / تسبقة / مسح، وزر «تسجيل غير المسجلين حاضرين».
3. **العمال**: بحث، الرصيد المستحق لكل عامل؛ **الملف**: الرصيد بارز بالألوان، المعلومات، الأسبوع الحالي، أرشيف كل الأسابيع مع حالة الدفع، كشف حساب PDF.
4. **أسبوع الدفع**: الأحد (معلَّم) + الاثنين–السبت مع المشروع والأجر، التسبقات، الإجمالي/التسبقات/الباقي، زر تأكيد الدفع أو بطاقة «مدفوع — مقفل».
5. **المشاريع**: المقبوض وتكلفة العمال لكل مشروع؛ التفاصيل مع سجل الدفعات الكامل وإضافة دفعة.
6. **الرواتب**: جدول أسبوعي لكل العمال مع تأكيد الدفع وتصدير PDF/Excel.
7. **التقارير**: يومي، أسبوعي، شهري، كشف عامل، تكلفة المشاريع، المقبوضات، التسبقات، الأرصدة — PDF و Excel.
8. **الإعدادات**: نسخ احتياطي/استعادة، رمز التصحيح، سجل المراجعة.

## 5. أخطاء الحساب المحتملة وكيف تُمنع

| الخطر | الوقاية |
|---|---|
| أخطاء الفاصلة العائمة | مليم `Long` + `BigDecimal`؛ اختبار 1000 نصف يوم بلا انحراف |
| احتساب الأحد في الأسبوع الخطأ أو مرتين | دالة `weekStart` واحدة + اختبار على كل أيام 2026–2027 |
| حضور مكرر لنفس اليوم | فهرس فريد (workerId, date) + upsert |
| خصم التسبقة مرتين | كل تسبقة مرتبطة بأسبوع واحد؛ لا يمكن إضافتها لأسبوع مدفوع |
| الدفع مرتين | فهرس فريد (workerId, weekStart) + فحص داخل المعاملة |
| تغيير الأجر يغيّر الماضي | `wageSnapshot` محفوظ مع كل يوم |
| اختفاء الباقي غير المدفوع | الرصيد دفتر حسابات تراكمي، ليس «أسبوعاً حالياً» فقط |
| تعديل أسبوع مدفوع بالخطأ | قفل + سبب + رمز + سجل مراجعة؛ اللقطة لا تتغير |
| فقدان البيانات | لا حذف للسجلات المالية، لا ترحيل مدمّر، نسخ تلقائي، نسخة أمان قبل كل استعادة |
| تسجيل يوم مستقبلي | مرفوض في الـRepository وفي منتقي التاريخ |
| دفع أسبوع لم يبدأ | مرفوض |
